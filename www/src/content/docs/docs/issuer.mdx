The `issuer` create an OpentAuth server, a [Hono](https://hono.dev) app that's
designed to run anywhere.

The `issuer` function requires a few things:

```ts title="issuer.ts"
import { issuer } from "@al-ummah-now/openauth"

const app = issuer({
  providers: { ... },
  storage,
  subjects,
  success: async (ctx, value) => { ... }
})
```

#### Add providers

You start by specifying the auth providers you are going to use. Let's say you want your users
to be able to authenticate with GitHub and with their email and password.

```ts title="issuer.ts"
import { GithubProvider } from "@al-ummah-now/openauth/provider/github"
import { PasswordProvider } from "@al-ummah-now/openauth/provider/password"

const app = issuer({
  providers: {
    github: GithubProvider({
      // ...
    }),
    password: PasswordProvider({
      // ...
    }),
  },
})
```

#### Handle success

The `success` callback receives the payload when a user completes a provider's auth flow.

```ts title="issuer.ts"
const app = issuer({
  providers: { ... },
  subjects,
  async success(ctx, value) {
    let userID
    if (value.provider === "password") {
      console.log(value.email)
      userID = ... // lookup user or create them
    }
    if (value.provider === "github") {
      console.log(value.tokenset.access)
      userID = ... // lookup user or create them
    }
    return ctx.subject("user", {
      userID
    })
  }
})
```

Once complete, the `issuer` issues the access tokens that a client can use. The `ctx.subject`
call is what is placed in the access token as a JWT.

#### Define subjects

You define the shape of these in the `subjects` field.

```ts title="subjects.ts"
import { object, string } from "valibot"
import { createSubjects } from "@al-ummah-now/openauth/subject"

const subjects = createSubjects({
  user: object({
    userID: string()
  })
})
```

It's good to place this in a separate file since this'll be used in your client apps as well.

```ts title="issuer.ts"
import { subjects } from "./subjects.js"

const app = issuer({
  providers: { ... },
  subjects,
  // ...
})
```

<NestedTitle id="issuerinput.issuer" Tag="h4" parent="IssuerInput.">issuer?</NestedTitle>
<Segment>
<Section type="parameters">
<InlineSection>
**Type** <code class="primitive">string</code>
</InlineSection>
</Section>
Fixed issuer URL, e.g. `https://auth.example.com`.

When set, it is used as the `iss` claim of issued tokens, in the
`/.well-known/oauth-authorization-server` document and when verifying
tokens. Request-derived values (Host, `X-Forwarded-Host`,
`X-Forwarded-Proto`, `X-Forwarded-Port`) are then ignored for the issuer
and for the default redirect_uri allow check.

When not set, the issuer is derived from the request URL and forwarded
headers (legacy behaviour).
</Segment>
<NestedTitle id="issuerinput.m2m" Tag="h4" parent="IssuerInput.">m2m?</NestedTitle>
<Segment>
<Section type="parameters">
<InlineSection>
**Type** <code class="type">M2MConfig</code>
</InlineSection>
</Section>
M2M (Machine-to-Machine) authentication configuration (optional).
Enables OAuth 2.0 Client Credentials Grant (RFC 6749 Section 4.4).

Requires `clientDb` to be configured for client authentication.
```ts

  clientDb: env.AUTH_DB,
  m2m: {
    ttl: 3600, // 1 hour token lifetime
    includeTenantId: true
  }
})
```

<NestedTitle id="pkce.requireforcodeexchange" Tag="h5" parent="IssuerInput.pkce.">requireForCodeExchange?</NestedTitle>
<Segment>
<Section type="parameters">
<InlineSection>
**Type** <code class="primitive">boolean</code><code class="symbol"> | </code><code class="primitive">any</code><code class="symbol"> | </code><code class="primitive">(clientId: <code class="primitive">string</code>) => <code class="primitive">boolean</code></code>
</InlineSection>
</Section>

<InlineSection>
**Default** false
</InlineSection>
Require PKCE or client authentication on every authorization code
exchange: a code issued without PKCE is only redeemed by a client that
authenticates (client_secret). Turn on once every client sends PKCE.
Independently of this flag, client credentials that are presented must
be valid.
</Segment>
<NestedTitle id="pkce.requireforpublicclients" Tag="h5" parent="IssuerInput.pkce.">requireForPublicClients?</NestedTitle>
<Segment>
<Section type="parameters">
<InlineSection>
**Type** <code class="primitive">boolean</code>
</InlineSection>
</Section>

<InlineSection>
**Default** false
</InlineSection>
Require PKCE on `/authorize` (response_type=code) for clients that are
registered in `clientDb` without a client secret (public clients).
Confidential clients and clients not registered in `clientDb` are not

<NestedTitle id="issuerinput.refresh" Tag="h4" parent="IssuerInput.">refresh?</NestedTitle>
<Segment>
<Section type="parameters">
<InlineSection>
**Type** [<code class="type">RefreshHook</code>](#refreshhook)
</InlineSection>
</Section>
Called on every refresh grant, before the refresh token is spent, to
recompute the subject's claims. Without it a refreshed access token
carries the properties frozen at sign-in for the refresh token's whole
life (a revoked role stays, a granted one never arrives).

- `{ properties }`: the new access token and the rotated refresh token
  carry these properties.
- `{ revoke: true }`: the user may no longer refresh (deleted, suspended):
  the token's family is revoked and the client gets `invalid_grant`.
- throwing: the claims could not be read. The client gets a retryable
  `503 temporarily_unavailable` and the refresh token stays unspent; stale
  claims are never served.
